## 現況

**フェーズ P0 相当（検証プロトタイプ）まで。**

ロードマップ（要件定義書 12 章）の P0 は「①本文↔盤面のスクロール連動 ②スマホでの盤面タッチ編集 の 2 点だけを作り、手触りを確かめる」ことを目的としている。これは、この 2 点が要件の中で最も「作ってみないと分からない」部分であり、うまくいかなければ設計全体を見直す必要があるため。

そのため現時点では、**保存機能がない**。リロードすると編集内容は消える。これは未実装ではなく、P0 の目的に対して不要だから入れていない。

### 設計上の要点

**本文と手順を別構造にしている。** 素朴には「棋譜の各手にコメントを付ける」（KIF 等と同じ構造）となるが、それでは棋書を表現できない。導入文・1 局面に数段落の解説・複数の変化をまたぐ総括が「1 ノード = 1 コメント」に収まらないため。詳細は `src/types/book.ts` の冒頭コメント。

**各ノードに SFEN を持たせている。** 冗長だが、局面検索（F-6-2）と解析キャッシュ（F-8-12）を木の辿り直しなしで実現するための意図的な選択。

**スクロール連動は IntersectionObserver で「読んでいる帯」を判定している。** スクロール量に逐一反応させると盤面がちらつくため。双方向連動の無限ループは、盤面側の操作で本文をスクロールしている間だけ本文→盤面の追従を止めることで防いでいる（`Reader.tsx` の `SUPPRESS_MS`）。

**`.reader` が PC・スマホのいずれでも唯一のスクロール領域。** IntersectionObserver の root として使い、帯の位置を割合で指定しているため。ページ全体がスクロールする構成に変えると連動が壊れる。

## 調整したい値

P0 の目的は数値の作り込みではなく手触りの確認なので、以下は暫定値のまま。実機で触って決める。

| 場所 | 値 | 内容 |
| --- | --- | --- |
| `Reader.tsx` `READING_BAND` | `-12% 0px -76% 0px` | 「読んでいる行」とみなす帯の位置 |
| `Reader.tsx` `SUPPRESS_MS` | `700` | 盤面操作後、本文→盤面の追従を止める時間 |
| `styles.css` `.board-area` (スマホ) | `min(100%, 38dvh)` | スマホでの盤面の大きさ |

## デプロイ

`main` への push で GitHub Actions が GitHub Pages へ公開する（`.github/workflows/deploy.yml`）。

初回だけリポジトリ設定が必要:
**Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。

公開先は `https://bonsai-human.github.io/shogiXbook/`。base パスはワークフローがリポジトリ名から自動で与えるので、リポジトリ名を変えても追随する。

## 既知の制約

- **GitHub Pages は COOP/COEP ヘッダを設定できない。** 将来 WASM エンジンのマルチスレッド版を使う際に効いてくる（要件定義書 9.3 / R-1）。開発サーバ側には `vite.config.ts` で設定済みなので、ローカルでの検証は問題なく行える。
- **保存機能がないため、リロードで編集内容が消える。** P1 で IndexedDB に載せる。
